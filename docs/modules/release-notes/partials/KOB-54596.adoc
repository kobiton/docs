== Debug on private devices over virtualUSB with AI assistants

AI assistants connected to the Kobiton MCP server can now debug an app on a private Kobiton device connected to your computer over virtualUSB. Organization admins can also check and change a host machine's virtualUSB settings without leaving the conversation.

*Highlights*

- `listDevices` accepts a new `virtualUsb` filter that returns the private devices ready for virtualUSB. When you name a device that is not ready, the response explains why.
- New `listHostingMachines` tool, for organization admins: shows each host machine's virtualUSB status, the next step when virtualUSB is not ready, and its max parallel tests. Filter by device or by machine.
- New `configureHostingMachine` tool, for organization admins: enables or disables virtualUSB, chooses routing, and sets max parallel tests. The change matches the same settings in *Device Management*, including ending active virtualUSB sessions when virtualUSB is turned off.
- New `debug-device-over-vusb` skill in the `automate` plugin 1.13.0: installs the pinned virtualUSB client, connects the device so it appears in `adb` or Xcode, runs the install, reproduce, and capture-logs loop, and always disconnects the device at the end.

*Availability*

- The skill runs on macOS and Windows. Linux is not supported.
- virtualUSB works with private devices only.

For details, see xref:ai:mcp/ai-plugin-mcp-ref.adoc[].
