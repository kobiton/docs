== Reset device state through the Kobiton API

Organization admins can now reset the state of devices in their organization using the new `RESET_DEVICE_STATE` task of the `POST /v2/execute-admin-tasks` API.

Resetting a device sets its state to `UNPLUGGED`, clears its booked status, and takes the device offline. The reset does not send any command to the physical device or its host machine. Sessions, reservations, history, and device settings are not changed.

* Reset up to 100 online devices in one request by listing their UDIDs.
* Review the result for each device in the response. The request returns HTTP 200 even when some devices fail to reset.
* The device stays offline until deviceConnect services are restarted. For details, see xref:device-lab-management:deviceConnect/restart-deviceconnect-services.adoc[].
* If the device has a live session, the session is disconnected and ends automatically.
* A reset does not send a `deviceStateChanged` webhook or a real-time update.

Available to users with the *ADMIN* predefined role, for devices in their own organization.

For request parameters, response fields, and error codes, see the https://api.kobiton.com/docs/#kobiton-api-v2[Kobiton API v2 reference].
