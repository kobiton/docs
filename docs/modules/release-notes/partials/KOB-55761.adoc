== Kobiton CLI: commands no longer act on the wrong session

When more than one CLI session is open, commands now stop with an error if `-s` names a different session from the one the session token belongs to. Previously, a command could act on two sessions at once: some actions applied to the session named with `-s`, while others applied to the session in the saved token, which belongs to the most recently created session.

* The error identifies the session token to pass, including when the token came from the saved `~/.kobiton/.session` file.
* With a single session open, commands run without `-a` or `-s` work as before.
* `session end`, `session terminate`, `session delete`, and `session show` still act on the session named with `-s`.
