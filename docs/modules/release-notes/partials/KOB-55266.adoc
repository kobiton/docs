== Scan completeness in the Kobiton MCP server

AI assistants connected to the Kobiton MCP server can now tell whether a session's validation scans have finished. Previously, a scan that was still running could return the same empty result as a finished scan with no findings.

- `getSession` returns a `scan_status` block with an entry for accessibility, crash, response time, and Flex Correct scans. Each entry is `complete`, `in_progress`, or `not_applicable`.
- `getAccessibilityValidationsSummary` returns a `scan_complete` flag that matches the accessibility entry in `scan_status`.
- `listCrashValidations` returns a `pending_count` of crash logs that are still being processed, so an in-progress crash is no longer reported as no crash.
- `getTestRun` returns `accessibility_scanning_status`, `crash_scanning_status`, and `network_payload_scanning_status` on each execution.
- The validation tool descriptions now tell the assistant that results may be partial while scanning runs and to check `scan_status` before treating a result as final.
