== Device passcode

- Fixed Kobiton generating a PIN passcode that a mobile device management (MDM) passcode policy could reject. A generated PIN no longer contains a run of three positions where each digit steps up or down by exactly 1, such as `123`, `321`, `232`, or `565`. Previously, only runs that moved in a single direction were blocked. A device whose MDM refused the passcode prompted for a passcode update and could go offline, because the passcode could not be applied.
- A PIN passcode submitted through the API is checked against the same rule. `POST /devices/{deviceId}/passcode/verify` now returns `400` for a PIN that contains a run such as `232`, which it previously accepted.

[NOTE]
====
PIN passcodes already set on devices before this change are not reissued. If a device still holds a passcode that your MDM rejects, contact Kobiton support to have it reissued.
====

_Applies to organizations with passcode mode enabled._
