== AI plugin and MCP

- The MCP tool `listAccessibilityValidations` and the REST endpoint `GET /v2/validations/accessibility` accept a `type` filter that narrows results to one accessibility finding type: `TOUCH_TARGET_SIZE`, `COLOR_CONTRAST`, or `CONTENT_LABELING`. Paging reflects the filter, so `total_items` matches that type's count in the accessibility summary.
- Accessibility findings are lean by default. Each item carries `id`, `command_id`, `type`, `issue_name`, and `standard`. Add the heavier fields with the `include` parameter, which accepts `element`, `metadata`, `screen`, and `screenshot_url`.
- Kobiton generates a screenshot URL only when `include` requests `screenshot_url`.
- An unrecognized `type` or `include` value returns HTTP 400 and names the accepted values.
- `GET /v2/validations`, used by Kobiton Portal, is unchanged and returns the full field set.
