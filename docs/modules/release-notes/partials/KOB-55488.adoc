== Test Management blocks Test Cases that a Test Run can't replay

Test Runs now refuse Test Cases that a Test Run can't replay, and Test Management shows the reason before you start a run.

- A Test Case can't run when its app wasn't installed from the app repository during recording, such as an app uploaded from a local file or installed from a URL in an automation session, or when the recording only uses the device home screen.
- In Test Management, *Run* is disabled for these Test Cases, with a tooltip that explains why and how to record them again. They can't be selected on the Test Run Setup screen or in *Customize* for a Test Suite.
- Creating a Test Run through the API or the `createTestRun` MCP tool returns a `400` error that names the Test Case and the reason.
- Test Case reads in the API return a new `run_blocked_reason` field.

Test Cases whose app comes from the app repository, and apps opened without an install, such as Chrome, run as before.

For details, see xref:test-management:test-cases.adoc#_test_cases_that_cant_run[Test Cases that can't run].
