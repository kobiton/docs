== Scan status and page limits in the Kobiton MCP server

- `getSession` now returns `scan_status`, which reports whether each validation scan for the session is `complete`, `in_progress`, or `not_applicable`. An AI assistant can tell findings that are still arriving from final results.
- `getAccessibilityValidationsSummary` now returns `scan_complete`, and `listCrashValidations` now returns `pending_count`, the number of crash logs still waiting to be processed.
- `getTestRun` and `listTestRuns` now return the accessibility, crash, and network payload scanning status of each execution.
- `listTestCases`, `listTestSuites`, and `listTestRuns` return at most 20 items per page, with a default of 10. `getUserInputEvents` now returns 10 events by default and at most 20 per call.
- `listDevices` now reports how many devices matched in total for each device list, along with the `limit` it applied.
- In the `automate` plugin 1.15.0, the `drive-automation-session` and `run-interactive-session` skills read a compact UI tree of the screen by default. The full page source is still available on request.

For details, see xref:ai:mcp/ai-plugin-mcp-ref.adoc[Kobiton AI plugin and tools reference].
