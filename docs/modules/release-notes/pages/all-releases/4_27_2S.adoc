== Back up and restore Kobiton data

Back up the data on a Standalone server while Kobiton keeps running, then restore it onto a target server that can take over if the primary server fails. Run `sudo kobictl run backup` on the primary server and `sudo kobictl run restore` on the target server.

*Highlights*

- Backup and restore require 4.27.1S or later on both servers.
- A backup includes the Kobiton databases and file storage, such as session videos, screenshots, and apps. The backup excludes the license file and SSL certificate.
- Back up to a remote destination over SSH, or to a local or mounted path.
- Restore replaces all Kobiton data on the target server.

== virtualUSB updates

virtualUSB connects dedicated Kobiton devices to your local development environment for tools such as ADB and Xcode. virtualUSB requires a Kobiton subscription plan that includes the feature.

*Highlights*

- virtualUSB supports devices running iOS 15 and 16, and iOS 17.4 through 27. For devices running iOS 12 through 14, contact Kobiton Support.
- A new virtualUSB CLI runs on Debian-based and Red Hat-based Linux distributions.
- Org Admins can enable or disable virtualUSB for each host machine from *Device Management*. On Standalone deployments, enter a *Connection Address* for each enabled host machine. Editing `dc.ini` on each host machine is no longer required.
- Filter *Device Management* to show only virtualUSB-enabled host machines, which display a *virtualUSB* badge.
- With the `debug-device-over-vusb` skill in the Kobiton automate plugin 1.13.0 or later, an AI assistant can connect to a device, install your app, reproduce an issue, and collect device logs. This skill supports macOS and Windows.
- The `listHostingMachines` and `configureHostingMachine` MCP tools let Org Admins check host machine availability and configure virtualUSB and Max Parallel Tests from an AI assistant.

For details, see xref:debugging:set-up-virtualusb.adoc[] and xref:device-lab-management:deviceConnect/enable-virtualusb-for-host-machines.adoc[].

== Fold and unfold Android devices during manual sessions

Manual sessions on supported foldable Android devices now include *Fold device* and *Unfold device* controls on the session toolbar. The session stream and *Inspector* adjust to the active screen.

*Highlights*

- Session Explorer records each fold or unfold action as a timeline step, with a screenshot of the device in its posture. Touch and swipe markers stay aligned with the captured screen.
- Book-style foldable devices, such as Galaxy Z Fold and Pixel Fold, are supported. Flip-style devices, such as Galaxy Z Flip, are not supported.
- The device keeps its folded or unfolded state between sessions.
- Fold and unfold actions are not supported during automated testing.

// Source: 2026-10-16.adoc (KOB-55167, KOB-55174)

== Passcode entry for iOS manual sessions

Enter device passcodes during iOS manual sessions, including passcode prompts for Apple Pay, Wallet, and the hidden apps folder.

*Highlights*

- When an iOS passcode screen appears, Kobiton Portal displays a keypad overlay. Enter the passcode on the overlay, or select *Auto-fill passcode* to use the device's configured passcode.
- The *Passcode helper* menu on the session toolbar shows or hides the keypad and auto-fills the passcode.
- The Devices page includes a *Passcode* filter with *Supported* and *Not Supported* options. Supported devices display a passcode icon in card and list views.
- Passcode entry requires passcode (PIN) mode for your organization and a passcode configured on the device.

Additional passcode fixes in this release, for organizations with passcode mode enabled:

- iOS devices with custom numeric passcodes unlock when you use *Power* to lock and unlock the screen in a manual session. Previously, you could be asked to enter the passcode on the physical device.
- Devices stay protected by a passcode, and compliant with MDM passcode requirements, after session cleanup.
- iPad passcodes persist when the device language changes during a session.

== Organization settings for Appium AI

Users with the *ADMIN* role or the `org_setting.modify` permission can configure Appium AI for the organization under *Settings* > *AI Settings*. New Appium sessions use the organization's LLM provider and locator settings without extra capabilities in test scripts.

*Highlights*

- Turn Appium AI on or off for the organization.
- Set the API format, base URL, API key, model, locator strategy, request timeout, and retry interval.
- Override most organization settings for a single session with `kobiton:*` desired capabilities.
- Changes apply to new sessions. Organizations without saved settings continue to use the host defaults.
- Appium AI is in Beta and is available on private and local devices only.

For details, see xref:automation-testing:appium-ai/configure-appium-ai-org-settings.adoc[Configure Appium AI settings for your organization].

// Source: 2026-10-16.adoc (KOB-54326, KOB-53282, KOB-55121)

== Kobiton MCP server

AI assistants connected to the Kobiton MCP server can read a session's validations one type at a time.

*Highlights*

- New tools: `listAccessibilityValidations`, `listCrashValidations`, `listResponseTimeValidations`, `listBlockerValidations`, `listElementSelectionValidations`, `listFlexCorrects`, and `getAccessibilityValidationsSummary`.
- Each list tool returns at most 20 findings per call, with `page`, `total_pages`, and `total_items` counts.
- `getAccessibilityValidationsSummary` returns accessibility counts by finding type and issue name, the number of steps scanned, and the time of the latest finding.
- `listAccessibilityValidations` filters by `TOUCH_TARGET_SIZE`, `COLOR_CONTRAST`, or `CONTENT_LABELING`. Request element, metadata, screen, and screenshot URL fields through the `include` parameter.
- AI assistants can tell whether a validation scan is still processing or complete.

Additional MCP server and plugin updates in this release:

- `/automate:setup` writes your Kobiton credentials without your API key passing through the AI assistant. If you shared a conversation from a setup run in an earlier plugin version, rotate that API key in *Settings > API Keys*.
- Device searches report the total number of matching devices. Results for Test Cases, Test Suites, Test Runs, and user input events are paginated.
- The automate plugin 1.15.0 uses a compact UI tree by default during interactive automation. The full page source is available on request.

== Reset stuck device states with the Kobiton API

`POST /v2/execute-admin-tasks` accepts a new `RESET_DEVICE_STATE` task. Org Admins can reset the recorded state of devices that remain in an incorrect state, such as a device that appears in use after its session has ended. The reset does not end active sessions or cancel reservations.

== List installed apps on devices with the Kobiton API

`GET /v2/devices/{deviceId}/installed-apps` and `GET /v2/devices/udid/{udid}/installed-apps` return the apps installed on a private device, including apps installed manually or through MDM. Results include each app's bundle ID, name, version, and build version.

== UiAutomator idle wait for Android automation sessions

Android Appium sessions support the `appium:waitForIdleTimeout` capability, which controls how long UiAutomator waits for an app to become idle before searching for elements. Change it during a session with the Appium Settings API. Set it to `0` to skip the idle wait for apps that update their interface continuously. The default is 10 seconds.

For details, see xref:automation-testing:capabilities/available-capabilities.adoc#_waitForIdleTimeout[waitForIdleTimeout].

// Source: 2026-10-16.adoc (KOB-54485)

== Session Explorer data for Kobiton CLI sessions

Kobiton CLI sessions can now populate Session Explorer and Session Overview. Capture is opt-in. Add `--capture` to `kobiton session create` with one or more data types, separated by commas.

*Highlights*

- `screenshots`, `view-trees`, and `metrics` add screenshots, view hierarchies, and device metrics to Session Explorer.
- `user-action` adds each user action to the session timeline.
- `video` and `logs` make the session video and device logs available in Session Overview.
- Session Explorer is available for a CLI session only when the session captures at least one data type and runs at least one `kobiton webdriver get` or `kobiton webdriver post` command.

For all data types, see xref:kobiton-cli:cli-commands.adoc#session-create-capture[Capture session data].

== Analytics report improvements

- The *Parallel Sessions* and *Retained Devices* reports count every hour a device was retained, including retains that have ended or expired. Previously, these reports could undercount retained devices.
- CSV exports of *Parallel Sessions* and *Sessions per Day* list one row per day in chronological order.
- *Device Utilization* exports are sorted by *Sessions*, with the most-used devices first.
- PNG exports of *Parallel Sessions* and *Sessions per Day* include the report's bar chart.

== Video reliability in manual sessions

Manual sessions now try to restore the full video stream after a brief interruption to the live device screen. Previously, the session switched to lower-quality screenshots for the rest of the session.

== Improved element inspection and interaction in Appium sessions

- Automation sessions on iOS and iPadOS can interact with system alerts, such as the Location Services alert. Previously, these commands could fail with `No active application elements`.
- On iOS 26, scripts can locate and select the buttons on location permission alerts, including *Allow Once*, *Allow While Using App*, and *Don't Allow*.
- *Appium Inspector* shows the correct XML hierarchy for each step of iPad automation sessions started without an app, such as a Safari session.
- On Android 13 and later, screens that contain web views now show their complete XML hierarchy, so element searches and interactions succeed.
- The WebDriver Get Element Attribute command returns `null` when an element does not have the requested attribute. Previously, it returned an error.
- Appium sessions support the `mobile: setText` command on Android and iOS. Previously, it returned a "not implemented" error.

== Improved reliability for iOS and iPadOS devices

- Developer Disk Image (DDI) mounting no longer fails intermittently on newer iOS devices, including iPhone 18 models on iOS 26.4 and later, or when a DDI is already mounted.
- Device cleanup resets time zone, language, and HTTP proxy settings on devices with newer iOS and iPadOS Settings layouts.
- When an XCTest runner fails to start, the device health check reports the runner error instead of an unrelated passcode error. The device keeps its passcode when the failure is unrelated to passcode configuration.
- App installs no longer leave unneeded files in temporary storage on host machines, which could cause installation failures from insufficient disk space.
- iOS devices that stop reporting web contexts recover when the next session starts, without a device reboot. This applies to Safari automation, Appium `autoWebview`, and other operations that use web contexts.
