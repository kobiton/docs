== AI plugin and MCP

- AI assistants connected to the Kobiton MCP server can now read a test session's validations one type at a time. Seven new tools cover accessibility, crash, response time, blocker, element selection, and Flex Correct findings: `listAccessibilityValidations`, `listCrashValidations`, `listResponseTimeValidations`, `listBlockerValidations`, `listElementSelectionValidations`, `listFlexCorrects`, and `getAccessibilityValidationsSummary`.
- Each list tool returns at most 20 findings per call, with `page`, `total_pages`, and `total_items` counts. An assistant pages through a large session instead of pulling every finding into context at once.
- `getAccessibilityValidationsSummary` returns a session's accessibility counts by finding type and issue name, with the number of steps scanned and the time of the latest finding, but not the findings themselves.
- `listAccessibilityValidations` filters by finding type: `TOUCH_TARGET_SIZE`, `COLOR_CONTRAST`, or `CONTENT_LABELING`. Items are lean by default. Request the element, metadata, screen, and screenshot URL fields through the `include` parameter.
- New paged REST endpoints back the tools: `GET /v2/validations/accessibility`, `/crash`, `/response-time`, `/blocker`, `/element-selection`, `/flex-correct`, and `GET /v2/validations/accessibility/summary`. The existing `GET /v2/validations` used by Kobiton Portal is unchanged.

== Reporting

- The *Device Utilization* report shows device usage by sessions, testing minutes, and unique users for a date range you select. Organization admins open it from *Reports*, under the *Device* category.
- The report lists device name, custom device name, manufacturer, OS, version, UDID, team, and public or private device type alongside the usage counts, sorted so the most-used devices appear first.
- Filter the report by date range and by public or private devices. Use the table search box to filter by team.
- Analytics reports now count every hour a device was retained, including retains that have since ended or expired. Previously, reports could show fewer retained devices than were actually retained.

== App installation

- Installing an app during a session no longer leaves a full-size copy of that app in temporary storage on the host machine. Previously, every install added a copy that was never reclaimed until deviceConnect restarted.
- Once temporary storage filled, installs on the affected host would fail with `Failed to install the application on the device` and `No space left on device`.
- Installing an iOS app no longer expands the entire `.ipa` on the host machine to read the app's metadata.
- Installing an app from the Apps repository now uses no additional temporary storage on the host machine. Install behavior is otherwise unchanged on iOS and Android.
- Copies left in temporary storage by earlier releases are removed when deviceConnect restarts.

[NOTE]
====
On iOS, the first install of a re-signed app still uses temporary storage while re-signing runs. This release does not change that.
====

== Device passcode

_Applies to organizations with passcode mode enabled._

- In manual sessions on iOS devices with a custom numeric passcode, selecting *Power* to lock the screen and selecting it again now unlocks the device automatically. Previously, the device stayed on the lock screen, app installation and other device operations failed, and users had to enter the passcode on the physical device.
- Devices with a 4-digit, 6-digit, or custom alphanumeric passcode continue to unlock automatically.
- On iOS 15.4.1 and 16.7.10, device preparation no longer stalls. Setting a device passcode no longer relaunches the *Settings* app repeatedly, and on-device automation no longer restarts in a loop.
- The device passcode is now set after the cleanup policy runs, so devices become available with a passcode after a session ends. Previously, cleanup removed the passcode after it was set, so the next session started on an unlocked device. Devices managed by a mobile device management (MDM) solution then opened to an MDM prompt requiring a passcode.
- iPad passcodes now persist through a device language change during a session. Previously, an iPad could return to *Available* without its passcode, and mobile device management (MDM) tools would flag it as having no passcode.

== Web context recovery for iOS sessions

- iOS sessions now refresh the device web inspector connection as the session starts. A device that has stopped reporting web contexts recovers on its next session, with no manual step on the device.
- This applies to every iOS session that reads a web context, including `appium:autoWebview` setup, Safari automation, and the web portion of the view tree capture.
- Previously, once a device entered this state, every later session on that device failed at setup with `Unable to find any web views`, and rebooting the device was the only way to clear it.
- A connection that breaks during a session stays unavailable for the rest of that session. The next session on that device starts with a working connection.
- Android sessions are unchanged.
