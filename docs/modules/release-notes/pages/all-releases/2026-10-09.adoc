== virtualUSB

virtualUSB lets you connect private Kobiton devices to your local development environment for debugging and testing. Connected devices are accessible through local development tools, including Android Debug Bridge (ADB) and Xcode.

=== Download virtualUSB

Download virtualUSB from the *Downloads* tab in Kobiton Portal. Installers are available for macOS, Windows, and Linux (Debian-based and Red Hat-based distributions).

== virtualUSB settings in Device Management

Manage virtualUSB on each host machine from the *Settings* dialog in *Device Management*. The dialog includes a *virtualUSB* tab for organizations whose plan includes virtualUSB.

- Enable virtualUSB on specific host machines and set how connections are routed: *Managed by Kobiton* for Kobiton-hosted machines, or *Self-managed* with an editable IP address for machines hosted by your organization.
- Host machines with virtualUSB enabled show a *virtualUSB* badge on their row in *Device Management*.
- Search by host machine name or IP address, or select *Show enabled only* to list only enabled host machines.

Available to organization admins with the *ADMIN* predefined role. Requires a plan that includes virtualUSB.

== Automatic routing for Kobiton-managed virtualUSB

- Host machines that use *Managed by Kobiton* routing for virtualUSB now have network routing set up automatically when virtualUSB is enabled. Routing is removed when virtualUSB is turned off or the host machine changes to self-managed routing. No IP address management is required.
- If routing setup fails, virtualUSB turns off on the host machine and the machine shows a failed status. Enable virtualUSB again to retry.
- *Managed by Kobiton* appears as a routing option only when Kobiton-managed routing is available for the organization.
- Host machines that use self-managed routing are not affected.

== Kobiton AI plugin: debug over virtualUSB

The `automate` plugin adds the `debug-device-over-vusb` skill. Describe a problem in plain language, and the skill debugs your app on a private Kobiton device over virtualUSB.

*Highlights*

- Installs the supported virtualUSB client before connecting. On macOS, the skill downloads, verifies, and unpacks the client. On Windows, the skill downloads and verifies the installer, then lists the remaining setup steps.
- Selects an online private device that is ready for virtualUSB, and asks you to confirm when more than one device matches.
- Checks known virtualUSB limitations before connecting, such as iOS 17.0 through 17.3 and iOS devices on Windows.
- Installs your build, reproduces the problem, captures device logs, and reports the results.
- Always disconnects the device when the session ends, including after a failure.
- `/automate:doctor` reports the pinned and installed virtualUSB client versions.

*Availability*

Requires `automate` plugin version 1.13.0 or later, an organization subscription that includes virtualUSB, and macOS or Windows. Linux and public devices are not supported.

For details, see xref:ai:mcp/ai-plugin-mcp-ref.adoc#_debug_over_virtualusb[Debug over virtualUSB].

== Host machine configuration in the Kobiton MCP server

- Organization admins can now configure a host machine from an AI assistant connected to the Kobiton MCP server. The new `configureHostingMachine` tool turns virtualUSB on or off, sets routing to managed by Kobiton or self-managed, and sets max parallel tests to unlimited or a custom value from 1 to 999.
- The tool applies all requested settings in one save, making the same change as the *Settings* dialog in *Device Management*. A request that matches the current configuration makes no change.
- The tool returns the machine's updated state. The response never includes the machine's IP address.
- `listHostingMachines` results now include each machine's max parallel tests setting.
- Turning virtualUSB off on a machine routed by Kobiton, or moving it to self-managed routing, ends the active virtualUSB sessions on its devices, as it does in Kobiton Portal.
- When a host machine reports `DISABLED` or `NO_NETWORK_ROUTE`, the `debug-device-over-vusb` skill offers an organization admin the option to enable virtualUSB and set routing, and asks before making the change. The skill never turns virtualUSB off or changes max parallel tests.

== virtualUSB host diagnostics in the Kobiton MCP server

- Organization admins can now ask an AI assistant connected to the Kobiton MCP server why a private device is not ready for virtualUSB. The new read-only `listHostingMachines` tool reports the virtualUSB status of the host machines behind your organization's private devices, with a specific cause and a next step.
- The tool reports whether virtualUSB is turned off on the host machine, no network route is configured, Kobiton-managed routing is still provisioning or failed to provision, or your organization does not have the virtualUSB add-on.
- Pass a device UDID to check only that device's host machine.
- The tool never changes machine settings and does not return IP addresses or MAC addresses.
- Organization members who call the tool receive the error `You don't have permission to do this action.` Ask an organization admin to check the host machine on the *Device Management* page in Kobiton Portal.

== Debug on private devices over virtualUSB with AI assistants

AI assistants connected to the Kobiton MCP server can now debug an app on a private Kobiton device connected to your computer over virtualUSB. Organization admins can also check and change a host machine's virtualUSB settings without leaving the conversation.

*Highlights*

- `listDevices` accepts a new `virtualUsb` filter that returns the private devices ready for virtualUSB. When you name a device that is not ready, the response explains why.
- New `listHostingMachines` tool, for organization admins: shows each host machine's virtualUSB status, the next step when virtualUSB is not ready, and its max parallel tests. Filter by device or by machine.
- New `configureHostingMachine` tool, for organization admins: enables or disables virtualUSB, chooses routing, and sets max parallel tests. The change matches the same settings in *Device Management*, including ending active virtualUSB sessions when virtualUSB is turned off.
- New `debug-device-over-vusb` skill in the `automate` plugin 1.13.0: installs the pinned virtualUSB client, connects the device so it appears in `adb` or Xcode, runs the install, reproduce, and capture-logs loop, and always disconnects the device at the end.

*Availability*

- The skill runs on macOS and Windows. Linux is not supported.
- virtualUSB works with private devices only.

For details, see xref:ai:mcp/ai-plugin-mcp-ref.adoc[].

== Emulators and simulators

Virtual devices (Android emulators and iOS simulators) now work across more Kobiton surfaces.

- The app repository now accepts iOS Simulator builds. Simulator apps show the Apple watermark and support the same app repository actions as other iOS apps, including search, versioning, download, and removal.
- The Kobiton API now supports additional operations on virtual devices, including installing applications, reserving devices, managing favorites, tags, and device names, and converting automation sessions into test cases.
- The Kobiton CLI supports installing applications on virtual devices.
- Device Bundles can include emulators and simulators. The device list in *Org Management > Device Bundles* now shows virtual devices with the *Type* `Virtual`. Bundles that include a virtual device show that device, including when you start a test run from the bundle.

== Device Management

Configure Max Parallel Tests for every host machine from one *Settings* dialog in *Device Management*. A single *Settings* button at the top of the page opens the dialog for all organizations, replacing the per-machine *Settings* button that used to appear on each host machine row.

- The *Max Parallel Tests* tab sets a limit of *Unlimited* or a custom value between 1 and 999 for each host machine. The *All machines* row applies one setting to every host machine at once.
- Search by host machine name or IP address.
- The `GET /v2/machines` API now returns each host machine's `max_parallel_tests` setting.

Available to organization admins with the *ADMIN* predefined role.
