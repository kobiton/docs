== virtualUSB expands with broader iOS support, Linux CLI, and easier configuration

virtualUSB connects dedicated Kobiton devices to your local development environment, making them available to development and debugging tools such as ADB and Xcode.

This release significantly expands virtualUSB with support for newer iOS versions, a new Linux CLI, centralized configuration in Kobiton Portal, and AI-assisted debugging through the Kobiton MCP server.

NOTE: virtualUSB requires a Kobiton subscription plan that includes the feature.

=== Expanded iOS support

virtualUSB now supports devices running iOS 17.4 and later, significantly expanding support for newer iOS devices.

The new virtualUSB version supports iOS 15-16 and iOS 17.4-27.

If you need to use virtualUSB with devices running iOS 12-14, contact https://support.kobiton.com/hc/en-us/requests/new[Kobiton Support].

=== New virtualUSB CLI for Linux

virtualUSB now supports Linux through a command-line interface (CLI). Linux users can connect dedicated Android and iOS Kobiton devices to their local environment for testing, debugging, and other device-level interactions.

The virtualUSB CLI supports Debian-based and Red Hat-based Linux distributions and is available from the *Downloads* link in Kobiton Portal.

=== Manage virtualUSB hosts from Kobiton Portal

Organization admins can now configure and manage virtualUSB for their host machines directly from *Device Management* in Kobiton Portal.

Previously, virtualUSB configuration required updating the `dc.ini` file individually on each Mac mini host. It could also be difficult for admins to see which hosts had been configured for virtualUSB.

The new *Device Management* experience provides a central place to:

* Enable or disable virtualUSB for individual host machines.
* Select the network routing type (*Managed by Kobiton* or *Self-managed*) and specify a connection address, when required.
* Search for host machines by name or IP address and filter the list to show only virtualUSB-enabled hosts.
* Identify virtualUSB-enabled hosts with a *virtualUSB* badge.

For details, see xref:device-lab-management:deviceConnect/enable-virtualusb-for-host-machines.adoc[].

=== AI-assisted debugging with virtualUSB

The Kobiton MCP server now supports AI-assisted debugging on dedicated devices through virtualUSB.

Using the `debug-device-over-vusb` skill in the Kobiton automate plugin, you can describe an issue in natural language and have your AI assistant connect to a device, install your app, reproduce the issue, and collect device logs.

Org admins can also manage virtualUSB through an AI coding assistant connected to the Kobiton MCP server. Use `listHostingMachines` to check host machine availability and identify configuration issues, and `configureHostingMachine` to enable virtualUSB, configure connection routing, and manage maximum parallel tests.

AI-assisted debugging with virtualUSB requires Kobiton automate plugin version 1.13.0 or later and supports macOS and Windows.

For details, see xref:ai:mcp/debug-over-virtualusb.adoc[] and xref:ai:mcp/virtualusb-mcp-tools.adoc[].

== Expanded Android emulator support across Kobiton

Android emulators now work across more Kobiton workflows, making it easier to use virtual devices alongside physical devices in your existing testing and device management processes.

=== More API operations for Android emulators

The Kobiton API now supports additional operations for Android emulators, including installing applications, reserving devices, managing favorites, tags, and device names, and converting automation sessions into test cases.

=== Install apps from the Kobiton CLI

You can now use the Kobiton CLI to install applications on Android emulators.

=== Add Android emulators to Device Bundles

Device Bundles for Scriptless automation can now include Android emulators, allowing you to include virtual and physical devices in the same bundle. Android emulators appear in the device list with the type *Virtual*.

== Centralized Max Parallel Tests configuration in Device Management

The new centralized *Settings* dialog in *Device Management*, which also includes virtualUSB configuration for eligible organizations, lets organization admins configure Max Parallel Tests for individual or all host machines from one place. The centralized dialog replaces the per-machine *Settings* button previously available on each host machine row.

- The *Max Parallel Tests* tab sets a limit of *Unlimited* or a custom value between 1 and 999 for each host machine. The *All machines* row applies one setting to every host machine at once.
- Search by host machine name or IP address.
- The `GET /v2/machines` API now returns each host machine's `max_parallel_tests` setting.

Available to organization admins with the *ADMIN* predefined role.
