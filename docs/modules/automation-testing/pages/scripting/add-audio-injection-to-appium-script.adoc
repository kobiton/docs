= Add audio injection to Appium script
:navtitle: Add audio injection to Appium script

Audio injection provides deterministic audio input during automated test sessions on iOS and Android devices. Use it to validate application behavior that depends on audio input, such as calls, voice input, and audio routing, without manual device interaction.

Audio injection simulates incoming audio only. It does not capture microphone input from the test environment.

== Supported platforms

* iOS (XCUITest automation engine)
* Android (UiAutomator2 automation engine)

== Before you start

* Enable Bluetooth on the device by setting the xref:automation-testing:capabilities/available-capabilities.adoc#_bluetooth[`kobiton:bluetooth`] capability.
* Host the audio file at a direct download URL the device can reach at runtime.
* Confirm the device is in a valid state to receive audio: connected call if applicable, unmuted, not in airplane mode.

=== Audio file requirements

|===
| Requirement | Value

| Container | WAV (16-bit), MP3, or OGG
| Sample rate | 8 kHz
| Channels | mono
| Max file size | 30 MB
|===

Use reliable, publicly accessible hosting so the runtime download does not delay test execution.

== Enable Bluetooth

Add the `kobiton:bluetooth` capability to your test configuration. This capability enables Bluetooth on the device during the session and is required for all audio injection commands.

.Example (JavaScript)
[source,javascript]
----
capabilities: {
    'platformName': 'iOS',
    'kobiton:bluetooth': true,
    'appium:deviceName': 'iPhone 15',
    'appium:app': 'kobiton-store:v1'
}
----

== Kobiton audio injection commands

Control audio injection through the `driver.execute()` method with Kobiton-specific command keys.

[options="header"]
|===
| Command | Description | Parameters
| `kobiton:startAudioInjection` | Begins playback of the specified audio file. | `url`: direct download URL for the audio file.
| `kobiton:pollAudioInjection` | Returns the current playback status. | None.
| `kobiton:stopAudioInjection` | Terminates audio playback and releases resources. | None.
|===

== Add audio injection to your script

The following example shows a full workflow: enable Bluetooth at session start, perform test actions, then start, poll, and stop injection.

.Example (JavaScript)
[source,javascript]
----
// Enable Bluetooth in capabilities
const capabilities = {
    'platformName': 'iOS',
    'kobiton:bluetooth': true,
    'appium:deviceName': 'iPhone 15',
    'appium:app': 'kobiton-store:v1'
};

// Initialize driver
const driver = await wdio.remote({
    protocol: 'https',
    hostname: 'api.kobiton.com',
    port: 443,
    path: '/wd/hub',
    capabilities
});

// Perform test actions (for example, initiate a call)
await driver.$('~Keypad').click();

// Start audio injection
await driver.execute('kobiton:startAudioInjection', {
    url: 'https://example.com/audio.mp3'
});

// Optional: poll playback status
const status = await driver.execute('kobiton:pollAudioInjection');

// Stop audio injection
await driver.execute('kobiton:stopAudioInjection');

// Cleanup
await driver.deleteSession();
----

Audio playback begins immediately after the start command and continues asynchronously while test execution proceeds.

== Best practices

=== Poll for playback completion

// REVIEWER QUESTION: What are all possible return values from `kobiton:pollAudioInjection`?

// not documented. If the contract is intentionally just "contains playing = active,"
// we should say so explicitly on the page. Flagging for confirmation from automation
// engineering before publish.

Fixed waits based on audio length work but can drift out of sync with actual playback. Poll `kobiton:pollAudioInjection` to detect completion dynamically.

.Fixed wait (JavaScript)
[source,javascript]
----
await new Promise((resolve) => setTimeout(resolve, audioLength * 1000));
----

.Poll for completion (JavaScript)
[source,javascript]
----
const startTime = Date.now();

while (Date.now() - startTime < maxWaitTime) {
    const status = await driver.execute('kobiton:pollAudioInjection');
    if (status == null || !String(status).includes('playing')) {
        break;
    }
    await new Promise((resolve) => setTimeout(resolve, 1000));
}
----

=== Clean up resources on failure

Stop audio injection and close the session in a `finally` block so failed tests do not leave audio routing active.

.Example (JavaScript)
[source,javascript]
----
try {
    // ... test code ...
} finally {
    try {
        await driver.execute('kobiton:stopAudioInjection');
    } catch (err) {
        // Ignore errors during cleanup
    }

    if (driver) {
        await driver.deleteSession();
    }
}
----

=== Validate device state before injection

Before starting injection, confirm:

* Bluetooth is enabled on the device.
* The call or audio-receiving state is active.
* The device is not muted.
* Airplane mode is disabled.

== Limitations

* Audio injection simulates incoming audio only. It does not capture live microphone input.
* Audio files are downloaded at runtime. Slow networks can delay playback start.
* Audio routing behavior differs between iOS and Android and may require platform-specific handling.
