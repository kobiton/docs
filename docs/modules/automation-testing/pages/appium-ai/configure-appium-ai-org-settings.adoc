= Configure Appium AI settings for your organization
:navtitle: Configure Appium AI settings
:description: Set the default LLM provider and locator settings that Appium AI uses for every Appium session in your organization.

Organization administrators set the default LLM provider and locator settings for Appium AI in Kobiton Portal. Every new Appium session in the organization uses these settings unless the session overrides them with desired capabilities.

Use organization settings to:

- Provide your LLM provider details to Kobiton once, instead of in every test script.
- Turn Appium AI off for your organization from a single place.

Appium AI is in Beta and is available on Private and Local devices. It is not available on Public Cloud devices.

== Requirements

- An administrator role in the organization.

== Turn Appium AI on or off for your organization

Use the organization-level Appium AI switch to turn Appium AI on or off for every session in your organization.

// TODO(docs-review): Confirm the switch label.

When you turn Appium AI off, natural language finds in your organization's sessions fail with the error `LLM client is disabled for this organization`. Session capabilities cannot turn Appium AI back on. Other session commands are not affected.

If Appium AI is off on the host running the session, natural language finds fail with the error `LLM client is disabled on this host`.

If your organization has never saved Appium AI settings, sessions use the host defaults configured by your Kobiton administrator.

The LLM provider settings are optional. If you turn Appium AI on without entering a provider, pass the provider settings in each session with `kobiton:*` capabilities. See xref:appium-ai/override-llm.adoc[Override Appium AI settings per session].

== How settings apply to sessions

- New Appium sessions use the saved organization settings on every device host in the organization. Appium AI reads your organization settings when a session starts.
- Sessions that are already running keep the settings they started with. Changes apply to the next new session.
- Desired capabilities passed in a session override the organization settings for that session only, one setting at a time. See xref:appium-ai/override-llm.adoc[Override Appium AI settings per session].

Appium AI resolves each setting separately. For each setting, it uses the first value it finds in this order:

. A capability passed in the Appium session.
. Your organization settings.
. The host defaults configured by your Kobiton administrator.
. The Kobiton default.

A session can combine values from different sources. For example, your organization settings can set the models while the session passes its own `kobiton:llmBaseUrl` and `kobiton:llmApiKey`.

[#api-key-rules]
=== API key rules

Appium AI sends an API key only to an endpoint chosen by the same source or a more specific source:

- If the session passes `kobiton:llmBaseUrl`, pass `kobiton:llmApiKey` in the same session. Appium AI does not send an API key from your organization settings or the host defaults to that endpoint.
- If your organization settings set the endpoint, Appium AI uses the API key from session capabilities or organization settings. The host default API key is never sent to that endpoint.
- If neither the session nor your organization sets the endpoint, Appium AI uses the API key from any source.

Your organization's API key is included in a session only when the device is owned by an administrator of your organization. On other devices, pass `kobiton:llmApiKey` in the session.

If no allowed API key is available, the first natural language find in the session fails with a missing API key error.
