= Configure Appium AI settings for your organization
:navtitle: Configure Appium AI settings
:description: Set the default LLM provider and locator settings that Appium AI uses for every Appium session in your organization.

Organization administrators set the default LLM provider and locator settings for Appium AI in Kobiton Portal. Every new Appium session in the organization uses these settings unless the session overrides them with desired capabilities.

Appium AI is in Beta and is available on Private and Local devices. It is not available on Public Cloud devices.

== Requirements

- An administrator role in the organization.
- An API key for the LLM provider, or a reachable endpoint that does not require a key.

== Open Appium AI settings

include::profile:partial$open-settings.adoc[]

Select the *AI Settings* tab. On the *Appium AI* card, select *Configure*.

The *Appium AI Configuration* page opens.

== Turn Appium AI on or off for your organization

Turn on *Enable Appium AI* to show the configuration fields. To turn off Appium AI for every session in your organization, turn off *Enable Appium AI* and select *Save*. When Appium AI is off, the *Appium AI* card on the *AI Settings* tab shows *Disabled*.

When Appium AI is off, natural language locators in your organization's sessions fail with the error `LLM client is disabled for this organization`. Session capabilities cannot turn Appium AI back on. Other session commands continue to work.

If Appium AI is off on the host running the session, natural language locators fail with the error `LLM client is disabled on this host`.

If your organization has never saved Appium AI settings, sessions use the host defaults configured by your lab administrator.

== Configure the LLM provider

. Under *Required Fields*, enter the following:
+
[cols="2,4,3", options="header"]
|===
| Field | Description | Session capability

| *API Format*
| API protocol format that matches the LLM provider. Select `OpenAiResponses`, `OpenAiChatCompletions`, `AnthropicMessages`, `KobitonChatCompletions`, `OllamaChat`, `AzureOpenAiV1ChatCompletions`, or `AzureOpenAiChatCompletions`.
| `kobiton:llmApiFormat`

| *Base URL*
| Base URL of the LLM provider.
| `kobiton:llmBaseUrl`

| *API Key*
| API key for the LLM provider. Kobiton Portal hides this field when *API Format* is `OllamaChat`.
| `kobiton:llmApiKey`
|===

. Optional: Under *Optional Fields*, change the following:
+
[cols="2,4,3", options="header"]
|===
| Field | Description | Session capability

| *Locator Strategy*
| Default strategy used to resolve natural language locators. Select *Find element by vision* (`visionvirtual`) or *Find element by view tree* (`uitree`). The form selects *Find element by vision* by default.
| `kobiton:locatorStrategy`

| *Model*
| Model used for Appium AI requests. Select a model from the list or type a model name. Available after you select an *API Format*.
| `kobiton:llmTextModel`, `kobiton:llmVisionModel`

| *Timeout Seconds*
| Timeout for LLM requests, in seconds. Default is `10`.
| None

| *Retry Interval Seconds*
| Interval between LLM request retries, in seconds. Default is `2`.
| None

| *Extra body*
| JSON object added to the request body of model calls to send model-specific parameters.
| `kobiton:llmTextExtraBody`, `kobiton:llmVisionExtraBody`
|===

Kobiton doesn't save the settings if *Base URL* is set without an *API Key*. This check doesn't apply to `OllamaChat`, which has no *API Key* field.

To discard unsaved changes, select *Cancel*.

After you save, *API Key* shows a masked value and the date and administrator who configured it, such as `Configured October 19, 2026 by <name>`. Kobiton Portal does not reveal a saved API key. To change it, select *Replace* and enter a new key.

=== Session-only settings

Kobiton Portal does not include the following settings. Set them per session with desired capabilities:

- `kobiton:llmApiVersion`: API version for Azure OpenAI endpoints.
- `kobiton:visionCoordSpace`: Coordinate space used for vision-based element location.
- `kobiton:llmTextModel`, `kobiton:llmVisionModel`, `kobiton:llmTextExtraBody`, and `kobiton:llmVisionExtraBody`: Separate models or extra request bodies for text and vision calls.

See xref:capabilities/available-capabilities.adoc[Available capabilities] for capability details and allowed values.

== How settings apply to sessions

- Appium AI reads organization settings when a session starts, on every device host in the organization.
- Running sessions keep the settings they started with. Changes apply to the next new session.

Appium AI resolves each setting separately, using the first value it finds in this order:

. A capability passed in the Appium session.
. Your organization settings.
. The host defaults configured by your lab administrator.
. The Kobiton default.

A session can combine values from different sources. For example, your organization settings can set the model while the session passes its own `kobiton:llmBaseUrl` and `kobiton:llmApiKey`.

[#api-key-rules]
=== API key rules

Appium AI sends an API key only to an endpoint chosen by the same source or a more specific source:

- If the session passes `kobiton:llmBaseUrl`, pass `kobiton:llmApiKey` in the same session. Appium AI does not send an API key from your organization settings or the host defaults to that endpoint.
- If your organization settings set the base URL, Appium AI uses the API key from session capabilities or organization settings. Appium AI never sends the host default API key to that endpoint.
- If neither the session nor your organization sets the base URL, Appium AI uses the API key from any source.

Appium AI includes your organization's API key only when an organization administrator owns the device. On other devices, pass `kobiton:llmApiKey` in the session.

If no allowed API key is available, the first natural language locator in the session fails with a missing API key error.
