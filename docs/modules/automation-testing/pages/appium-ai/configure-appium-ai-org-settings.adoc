Organization administrators set the default LLM provider and locator settings for Appium AI in Kobiton Portal. Every new Appium session in the organization uses these settings unless the session overrides them with desired capabilities.

== Requirements

- An administrator role in the organization.

== Available settings

[cols="2,5", options="header"]
|===
| Setting | Purpose

| LLM endpoint
| Base URL of the LLM provider.

| API key
| API key for the LLM provider. Required whenever an LLM endpoint is set, except when the API format is Ollama chat.

| API format
| API protocol format that matches the LLM provider.

| Text model
| Model used for UI tree-based operations.

| Vision model
| Model used for vision-based operations such as screenshot analysis. Must support image input.

| Extra body
| Optional. JSON passed into the request body of model calls to send model-specific parameters.

| Locator strategy
| Default strategy used to resolve natural language locators.

| Coordinate space
| Coordinate space used for vision-based element location.
|===

== How settings apply to sessions

- New Appium sessions use the saved organization settings on every device host in the organization.
- Sessions that are already running keep the settings they started with.
- Desired capabilities passed in a session override the organization settings for that session only. See xref:appium-ai/override-llm.adoc[Override Appium AI settings per session].
- If a setting is not set at the session or organization level, the session uses the default value.

If a session uses an LLM endpoint without an API key, the session fails with a missing API key error.
