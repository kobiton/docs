= Prepare Android device for hosting
:navtitle: Prepare Android device

Prepare an Android device before adding it to Kobiton Portal as a hosted device.

Different models of devices and versions of Android may have different layouts for settings and options. Refer to the device's manual if you cannot find the options mentioned in this document. In this guide, screenshots from _Samsung Galaxy_,  _Google Pixel_, and _Xiaomi Redmi_ devices are used as examples.

== Requirements

* A supported xref:supported-platforms:mobile-operating-systems-and-devices.adoc[Android device model].

* Additional requirements for Xiaomi models:

** A Mi account that you are signed in to. Create one on Xiaomi's https://account.xiaomi.com/[account page] if needed.

** A **SIM card** inserted. It does not need to be a working SIM card.

== Factory reset the device (optional)

A factory reset is strongly recommended for devices that were previously hosted by Legacy Kobiton or Legacy Gigafox. Refer to the device model's manual for factory reset instructions.

[CAUTION]
====
A factory reset erases all data on the device. Back up anything you need before proceeding.
====

[#enable_developer_mode]
== Enable Developer mode and USB debugging (required)

From the Home screen, swipe up to show all apps. Open **Settings**.

Follow the steps for your device type.

[tabs]
====

Most devices::
+
--

Scroll down and select **About phone**. For some models, such as Google Pixel, this option is under **System**.

Select **Software information**.

Tap **Build number** seven times. A popup appears when you are close to enabling Developer mode. If a lock screen is set, enter your security credentials when prompted.

Developer mode is now active.

image:device-lab-management:device-lab-management-android-prepare-usb-debugging-build-number.png[width=240, alt="Tapping Build number inside Software information seven times"]

Navigate back to the Settings main screen. Tap the newly available **Developer options** item. For some models such as Google Pixel, this option is under **System**.

Scroll down to the **USB debugging** option and turn it on. You can use the search function to quickly locate it.

Tap **OK** in the popup to confirm.

image:device-lab-management:device-lab-management-android-prepare-developer-options.png[width=240, alt="Newly available Developer options entry inside Settings"] -> image:device-lab-management:device-lab-management-android-prepare-usb-debugging-enable-usb-debugging.png[width=240, alt="Enable USB debugging inside Developer options"]

--

Xiaomi devices::
+
--

Select **About Phone**.

Tap **MIUI Version** (or **OS version** on HyperOS) seven times.

image:device-lab-management:device-lab-management-android-chinese-miui.png[width=240, alt="Tapping the MIUI version row in the About phone list"]

The message **You're now a developer!** displays. Developer mode is now active.

Find and open **Developer options** in **Settings**. On HyperOS, this option is under **Additional settings**.

Enable **Install via USB** and **USB Debugging (security setting)**. Depending on the Xiaomi model, enabling **USB Debugging (security setting)** requires either an inserted SIM card or a signed-in Mi account.

In **Developer options**, turn off the system-optimization setting. On MIUI, this setting is labeled **MIUI Optimization**. On HyperOS, it is labeled **Turn on system optimization**. Select **Accept** to confirm.

If the setting is not visible, tap **Reset to default values** repeatedly until it appears. The number of taps varies by model.

If system optimization is left on, Kobiton software cannot install or update deviceControl: a permission pop-up displays during installation, and the device does not come back online after a restart.

== Set the default USB configuration to **File transfer / Android Auto** (required)

On some Android models, Kobiton software cannot control the device unless the default USB configuration is set to **File transfer / Android Auto**. xref:#enable_developer_mode[Enable Developer mode and USB debugging] first.

Open **Settings** and navigate to **Developer options**. On Pixel devices, this option is under **System**.

Scroll down to the **Default USB configuration** option. You can use the search function to quickly locate it.

Choose **File transfer / Android Auto** or **Transferring files / Android Auto**, depending on the model.

image:device-lab-management:device-lab-management-android-prepare-usb-file-transfer.png[width=240, alt="File transfer / Android Auto selected on the USB configuration screen"]

[#disable_permission_monitoring]
== Turn on **Disable permission monitoring** (required for automation on some models)

On some Android models, permission monitoring revokes permissions that Kobiton software grants itself during a session, causing automation sessions to fail to start or stop responding partway through. xref:#enable_developer_mode[Enable Developer mode and USB debugging] first.

Open **Settings** and navigate to **Developer options**. On Pixel devices, this option is under **System**.

Scroll down to the **Disable permission monitoring** option and turn it on. You can use the search function to quickly locate it.

The setting's name describes what it turns off. Turning **Disable permission monitoring** on prevents the device from revoking permissions, which is what Kobiton software requires.

// Source: KOB-54010
[#disable_adb_authorization_timeout]
== Turn on **Disable adb authorization timeout** (required)

Turning on **Disable adb authorization timeout** keeps the USB debugging authorization between the device and its host from expiring. If the setting is left off, the authorization expires after seven days: the device goes offline, and the **Allow USB debugging** prompt displays on the device again.

This option is available on Android 11 and later. xref:#enable_developer_mode[Enable Developer mode and USB debugging] first.

Open **Settings** and go to **Developer options**. On Pixel devices, this option is under **System**.

Scroll down to the **Disable adb authorization timeout** option and turn it on. You can use the search function to quickly locate it. When the option is on, the toggle is blue.

== Turn off the passcode (required)

A device passcode prevents Kobiton software from controlling the device. If your organization requires passcode support, contact Kobiton Support to enable passcode mode. Passcode mode requires Android 10 or later.

In the **Settings** app, select **Lock screen**.

Select **Screen lock type**.

Select **None**. Enter the device's passcode or lock pattern if required.

image:device-lab-management:device-lab-management-android-prepare-disable-lockscreen-lockscreen-type-none.png[width=240, alt="Selecting None in the Screen lock type list"]

== Turn off **Auto Blocker** and **Block USB connections while locked** (Samsung devices with Android 14 and later)

On Samsung devices running One UI 6.0 (Android 14) and later, two security features can take devices offline. **Auto Blocker** prevents Kobiton software from controlling the device, and **Block USB connections while locked** disconnects the device's USB connection one hour after the lock screen activates.

Unlock the device if it is locked.

Navigate to **Settings** -> **Security and privacy**.

Turn off **Auto Blocker**.

image:device-lab-management:android-prepare-security-privacy-details.png[width=240, alt="The Auto Blocker security feature is disabled in the Security and Privacy settings on Android."]

Select **More security settings**, then turn off **Block USB connections while locked**.

image:device-lab-management:android-prepare-more-security-settings.png[width=240, alt="The Block USB connections while locked setting is turned off in the More Security Settings screen on Android."]

[#_prepare_foldable_android_devices]
== Prepare foldable Android devices

Keep book-style foldable Android devices, such as Samsung Galaxy Z Fold and Google Pixel Fold, unfolded when hosting them for testing.

Keep flip-style foldable Android devices, such as Samsung Galaxy Z Flip, open when hosting them for testing.

Stand foldable devices upright. When a device lies flat, the session stream can fail to adjust to the new screen after a fold or unfold.

For session behavior and limitations, see xref:manual-testing:foldable-devices.adoc[Foldable device considerations].

== Download Google Chrome (required for web automation)

If you plan to run web automation on the device, install Google Chrome from the Google Play Store.

== Turn off Google Play Protect

Google Play Protect scans the Kobiton agent app and can prevent it from controlling the device. If Play Protect cannot be turned off, select **Don't send** for the **deviceControl** app in the Play Protect popup that appears after plugging the device into the host machine.

Open the Google Play Store app.

At the top right, tap the profile icon.

Tap **Play Protect**, then tap the **Settings** icon.

Turn off **Scan apps with Play Protect** and **Improve harmful app detection**.

For more information, see Google's https://support.google.com/googleplay/answer/2812853?hl=en[support article about Play Protect,window=_blank].

== Prevent the screen from sleeping (optional)

Keeping the screen awake means testers do not need to re-wake the device during sessions. Skip this step to preserve battery life.

In the **Settings** app, scroll down and select **Developer options**. For some models, such as Google Pixel, this option is under **System**.

Find the **Stay awake** option and turn it on. Stay awake keeps the screen on only while the device is charging.

== Turn off auto-update for system software (optional)

An in-progress OS update takes the device offline until it finishes.

In the **Settings** app, tap **Software update**. Turn off **Auto download over Wi-Fi**.

== Turn off auto-update for apps (optional)

An in-progress app update can block the app from running until it completes.

Open the **Play Store**. Tap the **More options** icon (three vertical dots), then select **Settings**.

Expand **Network preferences**, then tap **Auto-update apps**.

Select **Don't auto-update apps** in the popup. Tap **Done** to save the changes.

image:device-lab-management:device-lab-management-android-prepare-turn-off-auto-update-apps-settings.png[width=240, alt="Opening the Play Store More options menu to reach Settings"] -> image:device-lab-management:device-lab-management-android-prepare-turn-off-auto-update-apps-do-not-auto-update-done.png[width=240, alt="Don't auto-update apps selected in the Auto-update apps dialog"]

== Turn off adaptive brightness (optional)

Turning off adaptive brightness lets Kobiton software keep the screen at minimum brightness, saving battery life.

In the **Settings** app, select **Display**.

Turn off **Adaptive brightness**.

== Turn off text correction and prediction for keyboards (optional)

Text correction can prevent Scriptless Automation test runs from executing as recorded. Turn it off if you plan to use Scriptless Automation on the device.

=== Samsung Galaxy devices

In the **Settings** app, select **General management**.

Tap **Samsung Keyboard settings**.

Turn off **Predictive text**.

image:device-lab-management:device-lab-management-android-prepare-disable-text-correction-samsung-predictive-text.png[width=240, alt="Predictive text turned off in Samsung Keyboard settings"]

=== Google Pixel devices

In the **Settings** app, select **System**.

Select **Languages & input**.

Select **On-screen keyboard**.

Tap **Gboard**.

Tap **Text correction**.

Turn off **Auto-correction**.

image:device-lab-management:device-lab-management-android-prepare-disable-text-correction-google-pixel-auto-correct.png[width=240, alt="Auto-correction turned off in the Gboard Text correction screen"]

The device is now prepared.
